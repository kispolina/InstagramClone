# Instagram Signup — Firebase

Екрани під’єднано до Firebase: вхід за email/паролем, реєстрація, лист підтвердження, відновлення пароля, профіль Firestore, вихід. Завантаження фото у Storage підключене у вебверсії.

## Запуск

1. Розпакуйте архів і відкрийте папку InstagramSignup у VS Code.
2. Виконайте `npm install`, потім `npx expo install --fix`.
3. Файл `.env` вже заповнений конфігурацією вашого проєкту instagramclone-f5611. Не замінюйте його порожнім шаблоном.
4. Вебдодаток Firebase вже зареєстрований. Analytics measurementId не потрібний для входу й бази даних.
5. Authentication → Sign-in method → увімкніть Email/Password. Перевірте Authorized domains для адреси вебзастосунку.
6. Створіть Firestore та опублікуйте `firestore.rules` у вкладці Rules.
7. Якщо потрібне завантаження фото, налаштуйте Storage та опублікуйте `storage.rules`. Перевірте вимоги тарифу у вашій Firebase Console.
8. Запустіть `npx expo start --web --clear`.

Використано Expo SDK 54. Версія Expo Go повинна підтримувати цей SDK; для першої перевірки використайте браузер.

## Перевірка підключення

- Create new account → email → дата YYYY-MM-DD → пароль → ім’я → нікнейм → фото/Skip → контакти → інтереси → Next.
- Акаунт створюється після введення пароля. Ім’я, нікнейм та інтереси зберігаються у Firestore після завершення останнього кроку.
- Якщо перервали заповнення, увійдіть з тим самим email та паролем: за відсутності профілю відкриється екран імені.
- Перевірте лист, відкрийте посилання та натисніть I verified my email. Демо-код 123456 більше не використовується.
- Після Log out перевірте повторний вхід і завантаження профілю.
- Forgotten Password? надсилає запит Firebase на лист відновлення.
- Перевірте наявність користувача в Authentication і документа users/{uid} у Firestore.

## Межі

SMS-реєстрація ще не налаштована: екран телефона пропонує email. Контакти не синхронізуються. Нікнейми поки не резервуються як унікальні. Дата перевіряється на клієнті, у Firestore не записується. Непідтверджений користувач може зберегти власний профіль; статус підтвердження показаний у застосунку.

Завантаження фото через вибране URI підтримано для браузера; на iOS/Android використайте Skip, доки не буде додано native адаптер. Пропуск фото не завантажує його на сервер. Паролі не зберігаються в Firestore та очищуються зі стану після авторизації. У native-середовищі сесія поки в пам’яті; веб використовує стандартну persistence Firebase.

Не додавайте service account або private key у .env: EXPO_PUBLIC потрапляє до клієнта. Тут потрібні лише Firebase client config. Доступ до даних обмежують опубліковані Rules.

Код обробників підключено до сервісів, але запити до вашого Firebase-проєкту не перевірено: конфігурацію вже внесено, але доступ до консолі та тестовий акаунт не надані. Модульні тести валідації: `npm test`.

Перевірка пакета: npm install успішний, JSX/JS синтаксис перевірено, npm test — 3/3, npx expo export --platform web — успішно. Наскрізні запити Firebase і візуальна перевірка не виконані.

Конфігурація instagramclone-f5611 внесена у .env. Read-only перевірка Firebase project config: HTTP 200. Чиста вебзбірка --clear містить цю конфігурацію. Вхід і запис профілю не тестувалися без тестового акаунта.
